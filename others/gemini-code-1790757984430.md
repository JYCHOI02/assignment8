# [과제 8 - 카드 1] 소개 페이지 공개/비공개 영역 분리 및 보안 구조 설계

## 1. 개요 및 목적
기존에 구현된 1번 과제(소개 페이지)를 기반으로, 누구나 볼 수 있는 **공개 영역**과 인증을 거친 사용자만 볼 수 있는 **비공개 영역(나만의 자리)**을 명확히 분리합니다.
단순히 프론트엔드에서 `display: none`으로 가리는 것이 아니라, 서버 단에서 비인가 요청을 차단하고 초기 HTML/JS 소스에도 비공개 데이터가 노출되지 않도록 구조화합니다.

---

## 2. 필수 준수 규칙 (보안 및 개인정보)
- **가상 데이터 사용**: 실제 전화번호, 주민등록번호, 실제 계정 정보 등 진짜 개인정보는 일절 포함하지 않습니다. 더미/가상 데이터로 구성합니다.
- **클라이언트 숨김 금지**: 비공개 데이터는 로그인 전 내려받는 HTML, JS 번들, CSS 소스 어디에도 평문으로 포함되어선 안 됩니다. 반드시 서버 API를 통한 지연/인증 로딩 구조여야 합니다.

---

## 3. 상세 요구사항

### 3.1 화면 UI 구성 (T08-C13, T08-C14)
1. **공개 영역**:
   - 기존 소개 페이지 내용(이름, 소개글, 기술 스택 등) 유지.
   - 비인가 사용자도 자유롭게 열람 가능.
2. **비공개 영역 (Private Dashboard)**:
   - 시각적으로 공개 영역과 명확한 경계선(카드 UI, 테두리, 구분 배너 등)을 둘 것.
   - 아래와 같은 **가상의 비공개 항목 3개 이상**을 배치(인증 전에는 잠김 상태 표시):
     1. `준비 중인 사이드 프로젝트 아이디어 노트`
     2. `지원 희망 기업 및 포지션 스크랩 목록`
     3. `월간 학습 및 역량 개발 자체 회고록`
   - 미로그인 상태에서는 "🔐 패스키 인증이 필요한 비공개 영역입니다"라는 잠금 UI 또는 안내 문구만 노출.

### 3.2 서버 API 및 접근 제어 (T08-C15, T08-C16, T08-C17, T08-C18)
1. **비공개 데이터 API 엔드포인트 구현**:
   - 예: `GET /api/private-data`
2. **인가 검증 로직**:
   - 인증 세션 또는 토큰이 유효하지 않은 요청일 경우, 데이터를 절대 반환하지 않고 즉시 **`401 Unauthorized`** 또는 **`403 Forbidden`** 응답 반환.
3. **소스 번들링 검증**:
   - 페이지 첫 로드 시 브라우저가 내려받는 정적 리소스(HTML 소스 보기, 응답 본문) 내에 3개 항목의 텍스트가 포함되지 않아야 함.

## 4. 검증 체크리스트 (통과 기준)
작업 완료 후 다음 6가지 기준을 만족하는지 확인해주세요:

- [ ] **T08-C13**: 공개 영역과 비공개 영역이 화면에서 시각적으로 명확히 구분되는가?
- [ ] **T08-C14**: 비공개 영역에 들어갈 항목이 3개 이상 정의되어 있는가?
- [ ] **T08-C15**: 패스키(인증) 전 상태에서는 비공개 영역의 실제 내용이 보이지 않는가?
- [ ] **T08-C16**: 미인증 상태에서 비공개 API(`/api/private-data`)로 직접 요청 시 거절되는가?
- [ ] **T08-C17**: 비인가 요청에 대해 `401` 또는 `403` HTTP 상태 코드가 반환되는가?
- [ ] **T08-C18**: 로그인하지 않은 상태의 페이지 초기 HTML 소스 코드에 비공개 텍스트가 전혀 없는가?

## 5. 전달할 산출물
1. 변경된 프론트엔드 및 백엔드(서버 라우트/API) 코드

   - 페이지 소스 보기를 했을 때 비공개 내용이 없음을 증명하는 방법
